## Visibility and scope

The rule is D-36: other players' Virtual Units bets are visible at any time, and
their lines stay hidden until the viewer's line lock opens. Two layers enforce it.

- **SQL.** For another player's row, `gtl_read_bets` returns only the side and
  units until the viewer's `gtl_markets_visible` gate opens that game's market.
  Line, odds, book, status, result and times are left out. The owner's own row
  and audit are never redacted.
- **API.** `projectBets` in `cloud/bets.mjs` redacts again unless the market is
  open through `gtl_read_bets_market` (`gtl_guess_revealed`). A closed market
  therefore stays closed unless both layers open it.
- **Roster.** A group selection filters the roster only. Picks stay
  account-level, so switching groups never copies or moves a pick.

API side (Gate M step 2):

- The deployed API (v32, from `8dccc5c`) already carries `POST /bets/read`.
- It maps both codes the SQL can raise: `GTL_COMMUNITY_MEMBER` (403) and
  `GTL_BETS_INVALID` (400).
- The route refuses signed-out requests. The release boundary already counts it
  as denied; only the three RPCs are listed as awaiting.

No web code calls `/bets/read` yet. Applying M-10 makes the signed-in route
answer, but changes no screen a player uses today.
