## Durable admission and safe lock-in

M-36 is `20261029165947_gtl_epl_moneyline_collector.sql`, generated by the installed Supabase CLI. Its actual schema
requirements are hosted M-30/M-32 only; pending M-33, M-34 and M-35 are independent. Applied M-32 is unchanged.
New private service-only invoker RPCs are `gtl_epl_moneyline_gate`, `gtl_epl_begin_moneyline_read`,
`gtl_epl_moneyline_due`, `gtl_epl_finish_moneyline_read` `gtl_epl_save_guess_current` and effect-free `gtl_epl_moneyline_save_ready`. Two private RLS tables retain durable attempts and append-only
collections. Browser roles have no table or function access. Collection records cannot be updated or deleted by service.

Every caller must pass the actual succeeded check history for that fixture's season/week: at least two distinct events,
each priced by at least two of DraftKings/FanDuel/BetMGM, valid bounded whole American prices, and the true availability
flag. Later skipped/negative checks cannot erase a passed week. JavaScript and SQL share the same recorded-gate bounds.

Both timed collection and the API hook require a separately configured, explicitly enabled `moneyline` schedule row.
The migration creates no row and enables nothing. This is an intentional launch prerequisite: until it is enabled,
a valid guess still locks and remains honestly pending when no reference exists, without a source request.
Only `supabase/admin/epl_moneyline_cron.sql` configures this collector, initially disabled. Do not replay the broader
`epl_jobs_cron.sql`: DNB-check creation/enablement is a separate action. No admin file is executed automatically.

The API integration contract is **save first with fresh trusted server time, refresh second, read back last**:

1. Member/input/deadline checks use the additive fresh-save wrapper, which locks the fixture, then samples database time
   and takes the later of that and the trusted service timestamp before invoking unchanged M-32. A request waiting across
   kickoff cannot backdate its save. There is no fallback to the old unsafe timing path; exact wrapper absence keeps saving
   unavailable and preserves the draft. Applied M-32 persists the accepted lock. Rejected or duplicate saves never invoke the hook.
2. `createEplMoneylineCollector({rpc,drawNoBet,clock}).refreshForLock({userId,eventId})` attempts one shared refresh.
   Admission requires the authenticated manager's genuine accepted lock within the last 30 seconds. It returns only
   `refreshed`, `cached` or `unavailable`; failures cannot throw through or undo the accepted lock.
3. Read the saved record again. An existing at-lock reference is immutable. Only missing references may resolve first-after.

The standalone `createEplMoneylineRefreshForLock` factory provides the narrow service adapter/source for the API
entrypoint. Missing odds credentials make zero RPC/provider calls. The worker likewise checks known missing configuration
before admission. No browser request directly reaches a provider, and neither ordinary reads nor rejected locks buy odds.

## Limits and atomic reference evidence

The fixture row lock is shared with applied M-32 saves. Admission atomically takes one credit from NFL/EPL's shared
conservative budget, preserving reserve 50 and paused/unknown states. No result, timeout or missing header refunds a
reservation. Reported quota can reduce the conservative balance and never raises it.

The durable limits are five-minute per-event spacing, six attempts per event per UTC day shared across lock and timed
callers, one two-minute lease at a time, at most one refresh per accepted lock, and at most two timed checkpoints per event
and stored kickoff (week open, then within three hours before kickoff). A missed open checkpoint is not replayed after
the late checkpoint begins. Failed and uncertain attempts consume the same limits before network I/O. Restarting the
worker cannot reset counters/checkpoints. Auth/rate-limit failures add shared five-minute backoff, and a scheduled batch
stops at its first unavailable event. The separate disabled job checks at most ten candidates per tick and reports
refreshed/cached/unavailable counts only.

Each source call is one bounded event request, without redirects/retries, and retains the raw-response SHA-256,
collection time and actual book/market observation times. Regular collection requires at least two complete allowed
books with exactly two known clubs, integer American prices in 100–100000 absolute value and observations within five
minutes before collection. Three-way, unknown, missing, stale or future evidence cannot become a scoring reference.
The median uses the normalized American line where −100 equals +100, including even-count half-away rounding.
No timestamp, club name, price or missing market is invented.

Finish revalidates the lease/token, current fixture identity/kickoff, enabled state, bounded source evidence and trusted
current time. A result arriving at/after kickoff, after lease expiry or after rescheduling writes no prices/reference,
even if it claims an earlier observation. Its quota still reduces the budget when available. Duplicate finish is inert.

Under the same fixture lock, one transaction appends the immutable both-club collection, upserts latest medians only
forward in time and resolves pending guesses from **that exact captured observation**. It never reads a later mutable
cache row as the first-after reference. A collection observed before/equal to a lock cannot resolve that pending guess;
no kickoff-late reference is allowed. The collection's event/time/median evidence survives every later cache update.

Applied M-32 stores integer distance. An extreme previously accepted pending guess whose distance exceeds that range
stays pending for review, with `unscorable_count` on the immutable private collection. Bigint calculation prevents it from
rolling back other managers' valid references. This is not a zero score or a claim that every pending reference resolved.
